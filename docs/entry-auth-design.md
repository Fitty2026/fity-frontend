# 진입/계정 화면 리디자인 설계 (feature/entry-auth)

- 날짜: 2026-07-18
- 브랜치: `feature/entry-auth` (develop에서 분기)
- 범위: 새 Figma 디자인 기준 4개 영역 — 앱 진입(스플래시 애니메이션), 서비스 소개, 로그인, 회원가입
- 범위 제외: 비밀번호 찾기 페이지(버튼 표시만, 추후 제거 가능성 있음), 실제 백엔드/소셜 OAuth 연동, "로그인 상태 유지" 실제 동작

## 1. 플로우 & 라우팅

기존 라우트 `/`, `/intro`, `/login`에 **`/signup`을 신규 추가**한다.

```
/ (스플래시 애니메이션) ─ 종료 후 자동 분기 ─┬─ 로그인 상태 → /home
                                            ├─ 인트로 시청함(fitty-intro-seen) → /login
                                            └─ 미시청 → /intro
/intro ─ 스와이프 or "다음" 버튼으로 슬라이드 이동, 마지막 슬라이드 "시작하기" → /login
/login ─ "회원가입하기" → /signup, 로그인 성공 → /home
/signup ─ "로그인하기" → /login, 가입 성공 → /login
```

- 인트로 시청 여부는 기존 `fitty-intro-seen` localStorage 키를 그대로 사용한다.
- 스플래시 종료 후 이동은 **자동**이다 (탭 불필요).

## 2. 스플래시 (`SplashPage` 재작성)

새 라이브러리 없이 Tailwind + CSS keyframes로 3단계 애니메이션을 구현한다.

1. **글자 낙하** — F, i, t, t, y 글자가 순차 딜레이를 두고 위에서 톡톡 떨어진다. 각 글자는 서로 다른 회전 각도로 흩어져 착지 (바운스 easing).
2. **로고 정렬** — 흩어진 글자가 하단 좌측의 "Fitty." 로고로 정돈된다 (fade cross 또는 transform 이동).
3. **마지막 화면 스윽 등장** — "Fit Your Style" 헤드라인 + 설명 문구 화면이 슬라이드 인으로 덮는다.

- 마지막 화면이 약 1초 보인 뒤 위 분기 규칙대로 `navigate(..., { replace: true })`. 총 3.5초 내외.
- 접근성: `prefers-reduced-motion` 시 애니메이션 생략하고 바로 마지막 화면 표시.

## 3. 서비스 소개 (`ServiceIntroPage` 리디자인)

- **Swiper** 라이브러리 사용 (develop에 의존성 추가되어 있음, 드래그 추종 스와이프).
- 레이아웃: **이미지 없음**. 좌측 정렬로 큰 숫자(1/2/3) + 큰 제목(여러 줄) + 작은 회색 설명 + dots + 하단 pill형 버튼.
- 슬라이드 1~2는 "다음" 버튼(다음 슬라이드로), 슬라이드 3은 "시작하기" 버튼(`fitty-intro-seen` 기록 후 `/login`).
- 우상단 "건너뛰기"는 새 디자인에 없으므로 **제거**한다.
- 슬라이드 문구 (Figma 확정):
  1. **내 옷으로 완성하는 코디** — 이미 가지고 있는 옷만으로도 가장 잘 어울리는 스타일을 추천해드려요
  2. **체형과 취향에 맞는 코디 추천** — 스타일 취향과 체형을 분석해 나에게 가장 잘 어울리는 코디를 찾아드려요
  3. **사진으로 미리 보는 실사 코디** — 사진을 합성해 실제처럼 미리 확인할 수 있어요
- 기존 `IntroSlide` 컴포넌트와 `intro-1~3.png` 에셋은 더 이상 사용하지 않으므로 정리(삭제)한다.

## 4. 로그인 (`LoginPage` 리디자인)

- 뒤로가기 없는 중앙 타이틀 "로그인" (헤더 백버튼 제거).
- 이메일 / 비밀번호 입력 — 비밀번호는 👁 아이콘으로 표시/숨김 토글.
- 입력칸 아래 줄: 좌측 "로그인 상태 유지" 체크박스(UI만, 동작은 API 연동 시 TODO), 우측 "비밀번호 찾기" 텍스트(페이지 없음, 동작 없음 — 추후 제거 가능성 있음).
- 검정 pill형(완전 라운드) "로그인" 버튼 → 기존 mock 로그인(`useLogin`) → `/home`.
- "또는" 구분선 → 소셜 버튼 3개: **Google(연회색 배경) / Apple(검정) / Kakao(노랑)**, 라벨 "○○로 시작하기", 아이콘은 inline SVG. 기존 mock 로그인 처리 유지.
- 하단 "계정이 없으신가요? 회원가입하기" → `/signup`.
- 폼 검증(zod): 이메일 형식, 비밀번호 6자 이상 (기존 유지).

## 5. 회원가입 (`SignupPage` 신규, `/signup`)

- 중앙 타이틀 "회원가입".
- 필드: **이름 / 아이디 / 이메일 / 비밀번호(👁 토글)**.
- zod 검증: 이름 필수, 아이디 4자 이상 영문·숫자, 이메일 형식, 비밀번호 6자 이상.
- Figma의 "로그인 상태 유지/비밀번호 찾기" 줄은 복사 실수로 판단해 **제외** (컨펌 완료).
- 검정 pill형 "회원가입" 버튼 → mock 가입(`authApi.signup`, 0.5초 지연) → 성공 시 `/login` 이동.
- 하단 "이미 계정이 있으신가요? 로그인하기" → `/login`.

### 폼 검증 규칙 (zod)

로그인·회원가입 공통으로 zod + react-hook-form으로 검증하며, 제약조건과 에러 메시지는 아래와 같다.

| 필드 | 사용 화면 | 제약조건 | 에러 메시지 |
| --- | --- | --- | --- |
| 이메일 | 로그인, 회원가입 | 이메일 형식 (`z.email`) | 올바른 이메일 형식이 아니에요 |
| 비밀번호 | 로그인, 회원가입 | 6자 이상 | 비밀번호는 6자 이상이어야 해요 |
| 이름 | 회원가입 | 1자 이상 (필수) | 이름을 입력해주세요 |
| 아이디 | 회원가입 | 4자 이상 | 아이디는 4자 이상이어야 해요 |
| 아이디 | 회원가입 | 영문·숫자만 허용 (`/^[a-zA-Z0-9]+$/`) | 아이디는 영문과 숫자만 사용할 수 있어요 |

- 형식 검증은 전부 폼에서 끝나므로 mock API에는 실패 케이스가 없다. 실제 API 연동 시 서버 오류(중복 아이디/이메일 등) 처리를 추가한다.

## 6. 공통 컴포넌트 변경

- `Input`: 우측 아이콘 슬롯(`rightElement`) 추가 — 비밀번호 토글용. 기존 사용처 영향 없음.
- 비밀번호 토글은 `PasswordInput` 등 auth feature 내 컴포넌트로 캡슐화.
- `SocialLoginButton`: provider별 배경색·아이콘·"시작하기" 라벨 반영.
- `Button`: pill형이 기존 스타일과 다르면 형태 옵션 추가 (기존 사용처 영향 없음).
- `authApi`: `signup(params)` mock 함수 추가 — 추후 이 파일 내부만 실제 API 호출로 교체.
- 체크박스는 로그인 화면 전용 소형 컴포넌트 또는 인라인로 구현.

## 7. 검증

- 자동화 테스트 프레임워크 부재로 이번 범위에서 테스트 제외.
- `npm run build`, `npm run lint` 통과 확인.
- `npm run dev`로 전체 플로우 수동 확인:
  1. `/` 스플래시 애니메이션(낙하 → Fitty. → Fit Your Style 슬라이드 인) 후 자동 이동
  2. `/intro` 스와이프·다음 버튼·dots 동작, 시작하기 → `/login`
  3. `/login` 폼 검증, 비밀번호 토글, mock 로그인 → `/home`, "회원가입하기" → `/signup`
  4. `/signup` 폼 검증, 가입 → `/login`, "로그인하기" → `/login`
  5. 재방문 시 `/` → `/login`(인트로 스킵), 로그인 상태면 `/` → `/home`

## 8. 커밋 규칙

- 커밋/푸시는 사용자가 직접 수행한다. 작업 단위마다 add 명령과 커밋 메시지를 복붙 가능하게 제공한다.
